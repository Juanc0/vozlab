# No-workspace message — v1

> Slice: horizontal (i18n → component → docs → captures).
> Context: [docs/components/web-pwa.md](../../components/web-pwa.md) §The layout,
> `apps/web/src/routes/(app)/+layout.svelte`.
> Opened: 2026-10-31 from a UI request: the "no membership" block of the
> `(app)` layout must read as a lack of access by the signed-in user (not as an
> empty tenant) and share the padding/card chrome of the graph view's floating
> bar.

## Goal

Reword and restyle the `no-membership` block rendered by
`(app)/+layout.svelte`. Done means: the heading and body state that the
signed-in user has no access to any workspace in this institution (without
implying the tenant is empty or hinting at how many workspaces exist), the
block uses the same padding (`px-7 py-3`) and card chrome (rounded card,
border, shadow) as the graph view's floating toolbar, the i18n keys are updated
in both languages, the component doc notes the change, and the gate stays green.
The `/join` link and the rest of the layout are untouched.

Decisions taken during scoping (2026-10-31):

- Styling: reuse the floating bar's padding and card chrome on the existing
  document section (no canvas, no real FloatingPanel).
- Wording: user-focused, neutral about workspace counts (see T2).
- Scope: only the `(app)` layout block; the `(auth)/join` no-membership
  branch is out of scope.
