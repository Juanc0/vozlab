## Goal

Done means: a tenant `ADMIN` can, from `/admin`, promote/demote an existing
tenant user between `USER` and `ADMIN` (and `MODERATOR`), and suspend/activate
a tenant user (invalidating their sessions), with row actions on the user list
and a separate "create workspace" tab; `/admin` and `/workspace-admin` are
organized into tabs where each tab holds one concern (list + row actions) and
general actions (create new) live in their own tab or a clearly separated
general-actions block; ADR-0050 records the carve-out that tenant admins manage
existing users' roles while the CLI remains the only door for the *first*
tenant admin; the role model docs and the web-pwa doc reflect the new capability.

## Out of scope (this version)

- User creation (users arrive via OIDC JIT) → not scheduled.
- User deletion / anonymization → needs PII erasure design (F4); deferred.
- A `status` column on `auth.users` → deferred; suspension uses
  `sessionsValidAfter`.
- Time-limited override grants → ROADMAP "Tracked, not scheduled".
- Workspace deletion/archive → `plans/workspace-lifecycle/v1` (not opened).
- `MODERATOR` new semantics → separate decision.
- Event QR scanner → existing backlog.
- Invitation email delivery → ROADMAP "Tracked, not scheduled".
