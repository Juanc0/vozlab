## Goal

One mechanism per credential and per identity concept, and zero cleartext
email in any database. Done means: every email-derived value lives as
`HMAC-SHA-256(lower(trim(email)), EMAIL_PEPPER)`; `workspace_join_codes` is
the only join-credential manager (router keeps only a `code_hash→tenant`
directory); `external_identities` is the only external-identity store; the
columns `users.email/provider_user_id/is_anonymous`, `workspaces.join_code/
auto_approve_join_code` and the tables `event_codes` and
`tenant_identity_providers` no longer exist; the seed produces a state the
real login flow can reach; local integration == CI == fresh volume.

## Global constraints (every task)

- Gate per checkpoint: `pnpm turbo run build type-check test` 9/9 +
  `pnpm lint` 0 errors + `uv run pytest` + `bash scripts/docs-hygiene.sh`,
  run WITHOUT output pipes; one commit per task; controller pushes after
  review (subagent-driven mode) — `docs/archive/plans/db-baseline/v1.md` set
  the rhythm.
- DDL tasks generate their folds ONLY after the previous fold is applied
  (append mode is the norm from the baseline on; never delete
  `meta/*_snapshot.json` again).
- DEC-8 discipline: wire/persisted bytes stay identical EXCEPT where a task
  explicitly retires them (T8 `?gid=`, T3 admin email display, T5
  `event_codes` consumers — the CLI is the only one).
- No cross-DB transaction (ADR-0002): router+tenant writes are sequenced,
  idempotent, with an explicit compensation order (tenant authority first,
  router directory second; revocation deletes the route first).
- Persisted audit discriminator values (`targetType:'global_identity'`) and
  the `global_user_events` trail are untouched.
- The dev volume is NOT reset mid-plan; folds migrate the existing volume
  forward. T8 does the single verification reset at the end.
