## Goal

Split the single mixed `/admin` page into two role-gated surfaces:

- `/admin` — **tenant administration**: workspace existence and creation
  (including workspaces the caller does not belong to), the tenant user
  directory, tenant cleanup, and a read-only break-glass roster with an
  explicit entry into a workspace.
- `/workspace-admin` — **workspace administration**: workspace profile,
  members and roles, join requests, invitations, workspace join codes, and
  event codes for `kind='EVENT'` workspaces.

Done means: a tenant `ADMIN` can create a workspace without joining it and
appoint its first workspace `ADMIN`; a workspace `ADMIN` with
`system_role='USER'` can run its workspace's door without tenant powers;
each surface is reachable only by its role and never answers with a raw API
403 as navigation; the two roles, their scopes and the ownership matrix are
documented in `docs/auth-and-tenancy.md`; and the multi-role union is
consistent across guards, use cases and `/auth/me`.

## Out of scope (this version)

- Workspace deletion or archive → `plans/workspace-lifecycle/v1` (not opened;
  register in ROADMAP when scheduled).
- Moving a member between workspaces → ROADMAP "Tracked, not scheduled".
- A UI for `system_role` changes → the ops CLI stays the only door
  (ADR-0041 §9).
- Giving `MODERATOR` new semantics → separate decision; it stays inert.
- Event QR scanner and anonymous join flow changes → existing backlog.
- Invitation email delivery → ROADMAP "Tracked, not scheduled".
- Changing the tenant-admin API bypass → it stays as documented break-glass.
- Rewriting the access routes → they already authorize a workspace `ADMIN`.
- Editing `kind` after creation or adding a DB CHECK for it → ROADMAP
  "Tracked, not scheduled".
- An audit-log UI for `auth.membership_events` → not scheduled.
- A global multi-tenant administration console → not a product concept.
