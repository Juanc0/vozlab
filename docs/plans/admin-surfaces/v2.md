## Goal

Remove the tenant-admin **bypass** over workspace administration: a workspace is
administered only by its ACTIVE workspace `ADMIN`s, never implicitly by a
tenant `ADMIN`. The tenant admin keeps institutional powers (workspace
existence/creation, tenant user directory, tenant hygiene) and loses every
workspace-scoped read and write — including the break-glass roster and the
"enter workspace admin" cross-workspace path. Done means: `WorkspaceAdminGuard`
and `assertWorkspaceAdmin` no longer special-case a tenant `ADMIN`;
`/admin` shows no member, role, invitation, join-code or event-code control
and no break-glass roster; `/workspace-admin` is reachable only with a
workspace `ADMIN` membership (no `?workspaceId` tenant override); and the
role model docs state that tenant and workspace administration do not overlap.

## Out of scope (this version)

- A time-limited, audited override grant for tenant admins → not scheduled
  (would be a new feature, not a bypass removal).
- Workspace deletion or archive → `plans/workspace-lifecycle/v1` (not opened).
- `system_role` management UI → ops CLI stays the only door (ADR-0041 §9).
- `MODERATOR` new semantics → separate decision.
- Event QR scanner / anonymous join flow changes → existing backlog.
- Invitation email delivery → ROADMAP "Tracked, not scheduled".
- Changing the ops/CLI emergency door → it stays.
