## Goal

One mechanism per credential and per identity concept, and zero cleartext
email in any database. Done means (read together with diagram §8.2 — the
layer-ownership table): every email-derived value lives as
`HMAC-SHA-256(lower(trim(email)), EMAIL_PEPPER)`; the router answers ONLY
"which tenant?" (`tenants/tenant_connections`) and "which human?"
(`global_users` vault + links + trail) — credentials are routed by a
generic `credential_routes(credential_hash, kind, tenant_id)` directory and
their AUTHORITY always sits in the tenant that enforces them:
`workspace_join_codes(+purpose)` for both workspace codes and event QRs,
`invitations` for both admin-same-tenant and external invitations
(72 h, single-use, revoke-on-resend everywhere); `external_identities` is
the only external-identity store; the columns
`users.email/provider_user_id/is_anonymous`, `workspaces.join_code/
auto_approve_join_code` and the tables `event_codes`, `global_invitations`
and `tenant_identity_providers` no longer exist; the seed produces a state
the real login flow can reach; local integration == CI == fresh volume.

## Global constraints (every task)

- Gate per checkpoint: `pnpm turbo run build type-check test` 9/9 +
  `pnpm lint` 0 errors + `uv run pytest` + `bash scripts/docs-hygiene.sh`,
  run WITHOUT output pipes; one commit per task; controller pushes after
  review (subagent-driven mode) — `docs/archive/plans/db-baseline/v1.md` set
  the rhythm.
- DDL tasks generate their folds ONLY after the previous fold is applied
  (append mode is the norm from the baseline on; never delete
  `meta/*_snapshot.json` again).
- DEC-8 discipline: wire/persisted bytes stay identical EXCEPT where a task
  explicitly retires them (T9 `?gid=`, T3 admin email display, T5/T6
  credential consumers — CLI + admin web are the only callers).
- No cross-DB transaction (ADR-0002): mint = tenant authority FIRST, then
  route; revoke = route deleted FIRST, then authority revoked; a missing
  route re-pushes; a stale route is inert (routing is never authority).
- Persisted audit discriminator values (`targetType:'global_identity'`) and
  the `global_user_events` trail are untouched.
- The dev volume is NOT reset mid-plan; folds migrate the existing volume
  forward. T9 does the single verification reset at the end.
